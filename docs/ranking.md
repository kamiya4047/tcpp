# Deterministic offline ranking baseline

The decoder first orders candidates by number of fuzzy edits, then number of completed/abbreviated syllables, then language score. This is a hard tier: increasing a word's frequency never lets a fuzzy correction beat an exact path. Specified wrong tones do not match. Tone omission costs 0.05 per syllable; prefix completion costs 0.7; curated phonetic confusions cost 3; a neighboring keyboard substitution costs 4. All of these are fixed, reviewable heuristics and can fall back to exact input by disabling typo tolerance/chaining.

For a phrase edge the baseline adds `log1p(editorial_prior) + 2 * syllable_count - 12 - phonetic_penalty`. The per-edge cost favors coherent dictionary phrases over unrelated character sequences. An original small table of contextual pairs adds 1.8 when the preceding text ends with an expected phrase, for example 跑 + 得 and 慢慢 + 地. Sensitive contexts ignore caller-provided preceding text. There is no hidden learning, remote call, or background input retention.

The complete beam produces a deterministic ordering with Unicode text as its final tie breaker. Duplicate surfaces are removed. The public candidate score is `80 - rank` (between 31 and 80 for the supported result limit), preserving the decoder's ordering inside the orchestrator without exposing unbounded accumulated scores. Confidence is 1.0 for exact/omitted-tone paths, 0.8 for prefix completion, and 0.65 for fuzzy correction. The provider is `bopomofo`; corrections are explicitly typed. Segment candidates use the same convention, with the selected context-aware path first.

The frequency values are original **editorial priors**, not corpus probabilities. The context table is a deterministic baseline, not a trained statistical or neural model. Neural reranking is not shipped in this decoder; enabling an optional neural setting must continue to use this local baseline until a separately licensed, evaluated runtime/model is integrated. A tiny invented weight table must not be represented as a validated language model.

Future model acceptance requires held-out top-1/top-3/MRR results against this baseline, exact/fuzzy invariants, warm/cold latency and memory measurements, disabled/failure fallback tests, a reproducible training manifest, and a documented license. Deterministic utility outputs, raw keys, and clipboard text must never be semantically reranked by the language model.
